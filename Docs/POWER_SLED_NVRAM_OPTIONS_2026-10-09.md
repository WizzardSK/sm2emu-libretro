# Power Sled NVRAM Settings And Initial Setup

## Implemented Scope

The approved operator fields are integrated in the Libretro adapter. Main
(`powsledm`) and Slave (`powsled`) each expose seven settings; Relay
(`powsledr`) exposes six. Existing menu conventions, the Disabled default for
NVRAM Settings, per-game visibility and the Enabled default for Automatic
Initial NVRAM Setup are retained.

| Setting | Programs | Values | Core Default |
| --- | --- | --- | --- |
| Ride ID | Main, Slave | Silver, Red, Black | Silver |
| Checkpoint 0 | All Three | 5–99 Seconds, Step 1 | 49 |
| Checkpoint 1 | All Three | 5–99 Seconds, Step 1 | 35 |
| Checkpoint 2 | All Three | 5–99 Seconds, Step 1 | 35 |
| Checkpoint 3 | All Three | 5–99 Seconds, Step 1 | 30 |
| Checkpoint 4 | All Three | 5–99 Seconds, Step 1 | 30 |
| Motion Angle | All Three | 10.0–45.0 Degrees, Step 0.5 | 38.0 |

Ride Silver is the native ROM initialization/fallback value, not a Service
Menu Use Default action. The checkpoint and angle defaults also match the
native operator defaults. Labels follow the shared Title Case formatter and
the existing `(Default)` value convention. Checkpoints are in seconds; Motion
Angle is the original cabinet motion limit, not a control calibration preset.

Country, the Relay's hidden Ride byte and automatic color/ID assignment are
not exposed or overridden. Dedicated Main/Relay/Slave programs still determine
their roles. Calibration menus remain listed only, and bookkeeping has no
Core Option.

## Storage And Save Ownership

Writes change only the selected fields at their proven offsets in each of
the three 28-byte settings copies. Checkpoints use unsigned little-endian
16-bit seconds; Motion Angle uses unsigned little-endian tenths of a degree;
Ride uses byte 8. Country, calibration/startup bytes, bookkeeping, other Backup
RAM bytes and EEPROM are preserved by manual overrides.

The layout gate requires three concordant settings blocks and valid numeric
ranges. Blank or discordant blocks are left to the game's native recovery;
the adapter retries its pending option application after emulation advances.
No native checksum is fabricated. The existing frontend save container CRC
remains separate and is regenerated by ordinary save export.

All three independently qualified complete initial images are embedded under
their own set names. Their common payload SHA256 is
`447fbd4f9d1c81d442a1658a108475fe02038c3385e772f111b393434fd9792f`;
the identity was established independently for each program. No parent-template
substitution is enabled for these variants. Seeding uses native settings and
zeroed native bookkeeping defaults. Existing matching frontend SRAM has first
priority; native save files suppress automatic seeding. No new automatic
override policy or automatic color assignment is introduced.

Generator: `scripts/generate-power-sled-nvram.py`. It checks the retained
qualification manifest and each image's length/hash, reuses the existing
template encoder, and replaces only marked Power Sled data sections.

of every new selector, exact three-copy writes, idempotence, unchanged bytes,
EEPROM preservation, blank/discordant rejection, complete frontend value lists
and per-game visibility. Existing option/template checks also pass: **331
options, 55 direct catalogs**. Input and Netpacket checks pass.

`scripts/test-power-sled-nvram-options.py` reuses the existing isolated linked
RetroArch runner and documented Service Menu navigation. Its one complete,
resumable five-stage recipe verifies all three programs:

1. Fresh automatic initial seeding with manual overrides disabled.
2. Manual overrides on existing SRAM: Checkpoints 5/99/51/30/60, Motion Angle
   25.5, Main Red and Slave Black; Relay's byte is preserved.
3. Fresh-process SRAM reload with manual overrides disabled.
4. Native `.nv`/`.eeprom` import without SRAM, preserving the saved settings.
5. Matching SRAM taking precedence over conflicting native files.

All **15 program records pass**. Screenshots independently verify all five
Checkpoints, Motion Angle and Main/Slave Ride colors. SRM identity/CRC, all
three settings copies, unrelated bytes/EEPROM, expected seeding logs, native
communication and clean process exit are checked. There are no remaining
runner-owned processes. Earlier failed harness/navigation attempts are retained
outside tracked source and excluded from accepted records.
