## Changes

### SCSP MIDI

Reading MIBUF consumes exactly one input byte. Reading only its status byte,
or merging a partial register write, does not consume input. Empty/full status
tracks both FIFOs. A byte arriving at a full input FIFO is dropped and sets
MIOVF; reading the input data acknowledges that flag. Pending-interrupt behavior
otherwise retains the existing SCSP implementation.

`Model2Sound::read8` now passes the actual 68000 byte lane to the SCSP, rather
than making a full word read and discarding half afterwards. Byte operations
outside the SCSP region retain their previous path and bus-wait accounting.

### MultiPCM

Voice registers 7, 8 and 9 update attack/decay, decay level and rate/release;
amplitude modulation uses register 10. Selecting a sample initializes the new
register view from its ROM header. Unknown registers no longer alias register 7.
The existing invalid-voice guard, frontend gains, pan, sample interpolation and
other approved audio behavior are retained.

Attack starts at the MAME reference attenuation and approaches maximum volume
using its fixed-point exponential equation. This changes the chip envelope,
not input response curves or frontend volume controls.

## Save States

Format **13** distinguishes the new register-selection semantics; the reader
continues accepting formats 4–12. Libretro's fixed 9 MiB container is unchanged.
Older core builds do not accept format-13 states.

MultiPCM's serialized eight-byte register image remains sufficient: the last
byte stores AM depth, and registers 7–9 are reconstructed from the envelope
parameters already serialized in `Sample`. A pre-13 state with register 7
selected is translated to register 10. Current states retain the new selection.
This avoids duplicate saved copies of the same envelope parameters.

SCSP MIOVF is stored in its native status bit in the existing serialized register
image, rather than adding a byte to every machine's payload. Loading an older
format initializes the previously unimplemented overflow flag to clear.

Existing states are readable, but continuation under corrected synthesis is not
a promise of bit-identical audio to older emulation behavior.

## Verification

- Libretro with Vulkan/OpenGL, standalone macOS and frontend-free targets build.
- ROM-free audio checks verify status versus data reads, 68000 byte lanes,
  write-side effects, FIFO overflow/order/status and overflow persistence.
- MultiPCM checks cover unknown registers, release versus AM, attack control,
  sample-exact current-state continuation and legacy AM-register migration.
  Golden PCM checkpoints use MAME's exponential attack reference equation.
- Existing sound-timing, drive-reply and Manx TT audio/AMS checks pass, including
  legacy state loading and intentionally rejected corrupt states.
- Old/new real-ROM ABI comparisons: Daytona and VF2 at 1,800 frames, Virtual On
  and STCC at 300 frames. Final video, full PCM and NVRAM hashes match in these
  bounded runs. They cover all four board variants and do not imply the changed
  corner cases occur in every captured sequence.
- Daytona and VF2 current-state round-trips replay deterministically and reject
  corrupted states. A genuine version-12 Daytona state generated by the prior
  core loads successfully and continues in the new core.
- Isolated RetroArch Vulkan/MoltenVK Daytona replay: 2,300 frames, clean exit,
  captured audio/video and valid SRAM. This is bounded frontend verification,
  not a subjective listening assessment or a complete-game campaign.

Evidence is retained under
`build-libretro-gpu/validation/mame-audio-20261019/`, including the explicit
pre-change core used for old/new and legacy-state comparisons. This binary is
a reproducible comparison artifact, not an installed-core rollback backup.
